Version Control Exercise
Continuity of updates
Steps: 
1. Github make a new repository using + sign on top. Enable public access, turn on README, and include a description of the repository. Name it as needed and create. 
2. Then, click green code button and "Open with Github Desktop" which once you click clone, will create a replica onto the Git Client
3. Once that's done, click "Open in Visual Studio Code" and we can edit the README tab and make sure to save it as needed. That saved work will show up in Git client (Github Desktop)
4. On the bottom left enter a summary of your changes and "Commit to main" 
5. Push to origin in order for it show up on the original Github repository and you're done!

NEW - Pull Request Workflow Exercise
1. On Github Desktop Click Main Branch -> "New Branch" -> Give it a name and create it. Then open VS Editor to adjust the code to this new branch. Save Code and commit with description and push to origin or publish first. It all applies to new branch that you created in Github Desktop. Can alternate between branches to see history of those specific branches
2. Publish branch on Github Desktop to Github Repo. Branch reflected into Github Repo, you can use the green button there to do pull request. However, you can go back to Github Desktop to Create the pull request. 
3. Hover over arrow next to Preview Pull Request and then Click "Create Pull Request" and click it. It brings you back to Github Repo and you can Give it a title, description of what it's for (developing PR Instructions). Once done click "Create Pull Request" on the bottom. Tabs on top lets you go to pull request or code. 
4. In Pull Request tab, select the title you just created and you can use gear icon in Reviewers to have others review the code. Going back to VS Code, make more commits as needed and push to origin on Github Desktop.
5. On Github Repo, in Pull Request Tab, you can see commits reflected and in conversation tab, you can add comments on the bottom. Click comment once done. Commits tab shows the different commits. The Files Changed tab also shows how files changed between branches so can be used to complete review.
6. Once review finalized, click Merge Pull Request. Squash and merge to combine into one commit, Merge pull request does all separate commits added to the main branch. Squash is preference.
7. Once done, you'll see all commit descriptions as one. Review and click "Confirm squash and merge"
8. Now that Github Repo is updated, we need to go into main branch in Github Desktop and "Fetch origin" to update the main branch here too and make it synced
